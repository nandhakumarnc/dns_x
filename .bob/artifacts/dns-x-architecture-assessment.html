1 — Repository Baseline

The repository is a frontend-only Vite + React SPA. No backend directory, no server code, no database migrations, no environment config, and no Python modules exist. The frontend is well-structured and partially functional, driven entirely by a 2-second mock-data generator.

Key insight: The frontend is production-quality and must be preserved as-is. The build-out strategy is additive: create a sibling backend/ tree and connect it to the frontend via the existing stub service files.

2a. Data Contract — What the frontend expects

The mock generator in src/data/liveState.js defines the exact shape that all frontend components consume via useDNSState(). The backend REST API and WebSocket events must produce compatible payloads.

{
  timestamp: number,
  system:        { status: "operational|degraded|critical", health: number },
  traffic:       { qps: number, peakQps: number, averageQps: number },
  performance:   { latency: number, cacheHit: number },
  errors:        { nxdomain: number, servfail: number, timeout: number,
                   rate: number, dominant: string, trend: "rising|stable|falling" },
  infrastructure: {
    gateway:   { status: string, qps: number },
    resolvers: [{ id, name, status, latency, qps }],
    cache:     { status: string, hitRate: number }
  },
  ai: {
    anomalyScore: number,     // 0–1
    outageRisk:   number,     // 0–100
    confidence:   number,     // 0–100
    baseline:     "normal|elevated|abnormal",
    severity:     "low|warning|critical",
    assessment:   string,
    signal:       string,
    recommendation: string
  }
}

2c. Navigation alignment note

src/lib/constants.js defines navigation labels Anomalies and AI Core as top-level routes (/anomalies, /ai-insights). The project spec says there should be no standalone "Anomalies" or "AI Core" pages — only Overview, Infrastructure, Incidents & Signals, Settings. Decision required before Phase 8 (frontend wiring): either consolidate these pages into the four canonical views, or keep the current six-route structure and map API data into all six. Recommendation: keep the six routes since they are already built; the spec was aspirational about navigation.

8 — Key Decisions & Constraints

Simulation Mode

  • DNS_X_SIMULATION=true in backend .env
  • Python telemetry is replaced by a scenario generator
  • Frontend mock interval retained as sim fallback
  • Identical pipeline code path as production

ML Layer Boundary

  • Node → Python via child_process.spawn or HTTP sub-process
  • Isolation Forest + XGBoost — no LLMs in real-time path
  • SHAP values returned as JSON feature-impact list
  • Fallback to rule-based classification if training data is sparse

Data Retention

  • Raw DNS packets are NOT stored
  • Metrics aggregated into 1m, 5m, 1h windows
  • Signals retained indefinitely (small records)
  • Resolver metrics auto-pruned at configurable TTL

Frontend Compatibility

  • Backend JSON shape must match liveState.js contract exactly
  • No frontend route changes required
  • All 6 existing pages remain; data source swapped incrementally
  • Tailwind / Vite / React versions untouched
